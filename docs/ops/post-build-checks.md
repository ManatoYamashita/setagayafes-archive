# ビルド後の検査

`dist/` を作った後に流す検査と、その測り方。予算の数値と規約は [conventions.md](../rules/conventions.md) の「性能の予算」が正本。

## 一覧

| 検査               | コマンド                                        | CI  | 見るもの                                                                      |
| ------------------ | ----------------------------------------------- | --- | ----------------------------------------------------------------------------- |
| JS が0             | `pnpm build`（後段の `scripts/guard-dist.mjs`） | ○   | `.js` ファイルの有無、markup の `<script>`・イベントハンドラ・script URL      |
| 公開禁止ファイル   | 同上                                            | ○   | ダンプ・バックアップ・ログ・サーバー側のコードなど                            |
| サイト内のリンク   | 同上                                            | ○   | このサイトへのリンクが `dist/` のファイルか、過去回のフォルダを指していること |
| 転送量の予算       | `pnpm test:e2e`（`e2e/budget.e2e.mjs`）         | ○   | 8つの画面で、初回と全体の非圧縮バイト数                                       |
| 外部リンクと過去回 | `pnpm check:links`                              | ×   | 過去回のフォルダと、他のホストへのリンクが応答すること                        |
| 本番のヘッダ       | `pnpm check:production`                         | ×   | 配置の後に、本番のヘッダが手元の Apache と同じであること                      |
| 本番のブラウザ確認 | `pnpm check:production:browser`                 | ×   | 配置の後に、本番のトップが崩れずに読み込まれ、MENU と絞り込みが動くこと       |
| Lighthouse         | 手動                                            | ×   | モバイルで全カテゴリ 100                                                      |

## サイト内のリンク（オフライン）

- `dist/` の markup（`href`・`src`・`srcset`・OGP の URL・sitemap の `<loc>`）と `robots.txt` の `Sitemap:` を読む
- このサイトの URL は、3つに分ける（`scripts/lib/links.mjs`）

| 分類   | 例                                              | 扱い                                                                                                                        |
| ------ | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 内部   | `/en/`・`/_astro/*.avif`・canonical・`og:image` | `dist/` にファイルが無ければ落とす。`#id` は、その id があることも見る                                                      |
| 過去回 | `/78th/`・`/tfa/`                               | このリポジトリの外（サーバー）にある。`src/data/` から導いた一覧（`scripts/lib/site.mjs` の `archivedPaths()`）にあれば通す |
| 外部   | `https://x.com/…`・Wayback Machine              | オフラインでは数えるだけ                                                                                                    |

- 末尾の `/` が無いディレクトリへのリンク（`/en`）も落とす。Apache は転送で直すが、1往復増える

## 転送量の予算（ブラウザで測る）

- 画像の候補は、画面の幅と DPR でブラウザが選ぶ。静的に「最大の候補」で足すと 1.5MB を超え、実際とかけ離れる。そのため Playwright の Chromium で、応答本文の非圧縮バイト数を測る
- **初回:** 画像以外（HTML とインラインの CSS、favicon）と、最初の画面に写る `<img>` の画像
  - 画面の下の `loading="lazy"` の画像を、ブラウザは先回りして読み込む（Chrome は下 1,250px ほど）。この先読みは数えない（2026-11-07 のオーナーの決定）
  - 理由: 先読みの量はブラウザと通信状況で変わり、最初の表示を遅らせないため
- **全体:** 開いたままの状態で最後までスクロールし、読み込まれたもの全部
  - 絞り込みは切り替えない（2026-11-07 のオーナーの決定）。切り替えるとカードの幅が変わり、同じ写真を大きい候補で取り直す（`sizes="auto"`）。この量は参考値として出力する
- 測る画面: 320（DPR 2）・390（DPR 3）・Lighthouse のモバイル（412×823・DPR 1.75）・768（DPR 2）・1023（DPR 2）・Lighthouse のデスクトップ（1350×940・DPR 1）・1440（DPR 2）・1920（DPR 2）
- 結果は `pnpm test:e2e` の出力に `ℹ initial … total …` の行で出る

## 外部リンクと過去回（`pnpm check:links`）

- 配置の前に、`pnpm build` の後で流す。他人のサーバーの状態で結果が変わるので、CI には入れない
- 過去回のフォルダ（`https://archive.setagayafes.org/78th/` など）と、他のホストへのリンクへ、HEAD（だめなら GET）を送る。同時に4本まで
- 2xx（転送の後）は通す。401・403・429・999 は「確かめられない」として表示だけする（X や Instagram は機械からの要求をこう断ることがある）。ブラウザで開いて確かめる
- それ以外（404・410・5xx・DNS や TLS の失敗・15秒のタイムアウト）は落とす
- 2026-11-07 の結果: 過去回23件・外部5件、すべて 2xx

## 本番のブラウザ確認（`pnpm check:production:browser`）

- 配置の後に、本番（`https://archive.setagayafes.org`）を Playwright の Chromium で開く。項目は [deploy.md](./deploy.md) の 5
- e2e（`pnpm test:e2e`）は手元の `dist/` を細かく見る。こちらは本番の配置の結果を見るもので、項目は「開ける・エラーが無い・MENU と絞り込みが動く」に絞る
- 部品の探し方は、e2e と共通の `scripts/lib/page-parts.mjs` に置く。markup を変えたら、ここだけを直す
  - MENU はアイコンのボタンで、文字は `aria-label` にしかない。文字で探しても見つからないので、ロール（`button`・名前 `MENU`）で探す
- ブラウザが自分で取り消したリクエスト（`net::ERR_ABORTED`）は数えない。絞り込みで隠したカードの遅延読み込みが、読み込み中に取り消されるため
- 共用サーバーなので、ページは1つずつ順に開く
- `check:production` と分けたのは、ブラウザが入っていない環境でも、ヘッダの確認は流せるようにするため

## Lighthouse（手動）

- 依存（`lighthouse` パッケージ）は足さない（2026-11-07 のオーナーの決定）。Chrome の DevTools で測る
- 手元（`pnpm preview`）と本番の両方で、モバイルの4カテゴリを測り、結果を Issue に記録する。手順は[配置の手順書](./deploy.md)の「8. 記録する」
- **手元は、本番と同じ CSP を付けて測る。** `pnpm preview` は `.htaccess` のヘッダを付けないので、CSP が原因の減点が出ない
- DevTools の代わりに、`npx` で一度だけ取得して走らせてもよい（`package.json` は変えない）。2026-11-08 にオーナーが許可した

```sh
# リポジトリの外で。版は公開から2週間以上たったものにする（2026-11-08 は 13.5.0）
npx -y lighthouse@13.5.0 https://archive.setagayafes.org/ \
  --only-categories=performance,accessibility,best-practices,seo \
  --chrome-flags="--headless=new" --output=json --output-path=ja.json
```

- PageSpeed Insights の API は、鍵なしの共有の枠を使い切られていることがある（2026-11-08 は 429）
- **どの要素が LCP になるかの結論は、Lighthouse（遅い回線を模した測定）で確かめてから書く。** 手元の速い回線での測定（Playwright の `PerformanceObserver` など）だけで決めない
  - 理由: 画像が届く時刻で、LCP になる要素が変わる。不透明度 0 で描かれた要素は、LCP の候補にならない。#34 の入場アニメーションでは、手元の速い回線だと、写真がアニメーションの最初のコマ（不透明度 0）で描かれ、候補から外れた。本番の Lighthouse では、写真はアニメーションが始まった後に届き、そのまま LCP になった。手元の結果から「Lighthouse は写真を測らなくなる」と書いて、PR #36 で直した
  - Lighthouse の JSON では、LCP の要素は `lcp-breakdown-insight` の `details` の中の `selector` にある（13.5.0。`largest-contentful-paint-element` の監査は無い）

### 2026-11-08 の本番の実測と、SEO 92 の原因

- 本番の `/`・`/en/` は、性能・アクセシビリティ・おすすめの方法が 100、SEO が 92 だった
- SEO の減点は `robots-txt` の監査（0点、「CSP violation」）。Lighthouse は robots.txt を、測っているページの中から取得する。CSP に `connect-src` が無いと `default-src 'none'` が効き、取得が禁じられる
- CSP に `connect-src 'self'` を足した（理由は [htaccess.md](../design/htaccess.md)）。`e2e/headers.e2e.mjs` と `pnpm check:htaccess`・`pnpm check:production` が、この退行を検査する
