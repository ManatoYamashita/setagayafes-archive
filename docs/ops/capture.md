# サムネイルの撮影

各回のサイトのトップを撮影し、一覧のサムネイルと OGP 画像の元にする。決定の経緯は Issue #1 の ToDo 3。

## 流れ

1. `pnpm capture` で各回のトップを撮影する。原画像は `src/assets/captures/` に保存され、コミットする
2. `pnpm build` のときに、Astro の画像処理（`astro:assets`）が原画像から次を作る
   - 表示寸法の AVIF（カード・ヒーロー）
   - OGP 用の JPEG（1200×630）
3. AVIF と JPEG はコミットしない。`dist/_astro/` に出力される

AVIF と JPEG をビルド時に作るのは、次の理由による。

- 表示寸法は画面の設計で変わる。寸法を変えても撮り直さずに済む
- 画像処理は Astro が同梱する sharp で行う。依存を足さずに済む
- リポジトリに入れるのは原画像だけで済む

## 使い方

```sh
# 初回だけ。撮影に使うブラウザを入れる
pnpm exec playwright install --only-shell chromium

pnpm capture          # 全回
pnpm capture 98       # 第98回だけ（年次の追加）
pnpm capture 90 96th  # 複数
```

- 撮る回は festivals データ（`src/data/festivals.ts` の `FESTIVALS`）から読む。データに無い回は撮れない
  - 新しい回は、先にデータへ1件足してから `pnpm capture <回>` を流す
  - `pnpm test` は、データの全回に原画像があることを検査する。データと原画像は同じ PR に入れる
- URL はデータの `pathOf`（`/81st/` など）から作る。`externalLink` を持つ回（このホストにサイトが無い回）は、`OVERRIDES` に写真を指定しないとエラーになる
- 撮影は手元で行う。CI では行わない
- 1回ずつ順に撮る（共用サーバーへの負荷を抑えるため）。全回で約3分
- 撮影に失敗した回は、原画像を書き換えない（一時ファイルへ書いてから置き換える）

画面からは `src/lib/captures.ts` を使う。

| 名前                  | 内容                                                                   |
| --------------------- | ---------------------------------------------------------------------- |
| `captureOf(回数)`     | 原画像（`ImageMetadata`）。`<Image>`・`<Picture>` の `src` に渡す      |
| `CAPTURE_IMAGE_PROPS` | 全サムネイルで共通の指定（AVIF、`fit: "cover"`、上端を基準に切り出す） |
| `ogImageOf(回数)`     | OGP 用の JPEG（1200×630）                                              |
| `hasCapture(回数)`    | 原画像の有無                                                           |

## 撮影の条件

全回を同じ条件で撮る。変えてよいのは、読み込み後の待ち時間だけ。

| 項目           | 値                                                 |
| -------------- | -------------------------------------------------- |
| ブラウザ       | Playwright の Chromium（headless shell）           |
| 画面           | 1280×800（CSS px）、`deviceScaleFactor` 2          |
| 原画像         | PNG、2560×1600                                     |
| 言語・時刻     | `ja-JP`・`Asia/Tokyo`、ライトモード                |
| 待ち方         | `load` → `networkidle`（最大15秒）→ フォント → 3秒 |
| アニメーション | 撮影時に止める（`animations: "disabled"`）         |

- 1280px にしたのは、現在のサイトのデスクトップ表示が収まり、2004〜2011年の幅 800px のサイトも中央に収まるため
- フォントは撮影した機械のものになる。macOS で撮る
- 回ごとの設定（待ち時間・写真）は `scripts/lib/capture-targets.mjs` の `OVERRIDES` に置く。キーはデータにある回でなければならない（`pnpm test` で検査する）

## 回ごとの例外

| 回               | 扱い                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| 87th             | サイトが残っていない。旧トップの `img/87th.JPG` を取得し、メタデータを除いて保存する |
| 94th             | 約10秒のローダーがあるので、待ち時間を13秒にする                                     |
| 75th・80th・81st | トップは入口のページ（画像だけ）。当時の姿としてそのまま撮る                         |

第87回の写真は、全回の撮影では、原画像が無いときだけ取得する。`pnpm capture 87` と回を指定すると取得し直す。

旧トップの部品（`img/` を含む）を公開フォルダの外へ退避した後は、`img/87th.JPG` を取れない（[配置の手順書](./deploy.md)の 7）。原画像は `src/assets/captures/87th.jpg` にあるので、撮り直す必要は無い。取り直したいときは、サーバーの `~/archive-docs/deploy/old-top/img/87th.JPG` を一時的に戻す。
旧トップの `/img/` は、差し替えの後に公開フォルダの外へ退避する（Issue #1）。退避した後は取得できない。

### 写真のメタデータ

写真は再エンコードせずに、メタデータの区画だけを除く（`scripts/lib/jpeg.mjs`）。

- 除くもの: EXIF・XMP（APP1）、IPTC（APP13）、MPF の埋め込み画像（APP2）、コメント、終端の後ろのデータ
- 残すもの: JFIF（APP0）、ICC プロファイル（APP2）、Adobe（APP14）。色の再現に要るため
- EXIF の向き（Orientation）が 1 以外の写真は、除くと横倒しで表示されるため、エラーにする
- `pnpm test` で、`src/assets/captures/` の JPEG にメタデータが無いことを検査している
